# Лаба 1. FIM: создание, изменение и удаление файла

**Дата:** 22.10.2026 · **Агент:** Win10-Host (001) · **Wazuh:** 4.14.9

## Цель

Увидеть, как модуль FIM (syscheck) фиксирует создание, изменение и удаление файла в наблюдаемой папке, и разобрать алерты.

## Условия

- Наблюдаемая папка: `c:\fim_test`, режим `realtime` (поле `syscheck.mode` в алерте).
- Тестовый файл: `c:\fim_test\live_test.txt`.
- Для лабы взята отдельная папка, а не реальная папка автозагрузки. Механика та же. Для папки автозагрузки в `<syscheck>` агента добавляется путь `%PROGRAMDATA%\Microsoft\Windows\Start Menu\Programs\Startup`, а техника в таком случае T1547.001.

## Что сделал

1. Создал пустой файл `live_test.txt`.
2. Дописал в него данные (стало 13 байт).
3. Удалил файл.

## Результат

| Действие | Время (UTC+5) | Rule ID | Level | Описание | Событие |
|---|---|---|---|---|---|
| Создание | 19:03:53 | 554 | 5 | File added to the system | `added` |
| Изменение | 19:04:54 | 550 | 7 | Integrity checksum changed | `modified` |
| Удаление | 19:07:10 | 553 | 7 | File deleted | `deleted` |

Алерты приходят практически сразу: время алерта о создании `19:03:53.126`, совпадает с временем файла, то есть задержка меньше секунды (режим `realtime`).

Хэши и размер из алертов:

| | До | После |
|---|---|---|
| Размер | 0 байт | 13 байт |
| SHA-256 | `e3b0c44298fc1c149afbf4c8996fb92427ae41e4649b934ca495991b7852b855` (хэш пустого файла) | `ee9204e6c0b79cb90fe43fa94cfa4fafc5e23ee25783a4edbb48b2049eabf7e2` |

В алерте об изменении `syscheck.changed_attributes`: `size, mtime, md5, sha1, sha256`.

## Вопросы для разбора

**Почему вредоносы любят папку автозагрузки?**
Это простейший способ закрепиться: файл в папке запускается автоматически при входе пользователя. В пользовательской папке автозагрузки для этого не нужны права администратора и вмешательство в системные службы.

**Какие данные из алерта проверить первыми, если файл появился без вашего ведома?**
Хэш `sha256_after` (поиск по базам угроз и в антивирусах), полный путь и расширение, время появления.

**Что FIM не покажет и чем это дополнить?**
Не показывает процесс, создавший файл, и пользователя. Дополнение: режим `whodata="yes"`, который на Windows опирается на аудит доступа к объектам (событие 4663), а также аудит создания процессов (событие 4688) или Sysmon (Event ID 1), чтобы связать файл с процессом.

## Выводы

- FIM фиксирует факт и содержимое изменения (хэши, размер, время) практически мгновенно в режиме `realtime`.
- По хэшам до и после видно, что содержимое изменилось. Для пустого файла хэш `e3b0c442…` это хэш пустой строки, его легко узнать.
- Без `whodata` невозможно ответить на вопрос «кто и чем это сделал».
