# Лаба 5. Укрепление Windows 10 по CIS (SCA)

## Цель

Показать цикл «обнаружили слабое место → исправили → проверили» на модуле SCA (Security Configuration Assessment).

## Исходное состояние

Политика: CIS Benchmark для Windows 10. На скриншоте скана ([скриншот](screenshots/01-sca-cis-windows10-score.png)): Passed 111, Failed 308, Not applicable 5, оценка 26%.

## Что исправил

| ID проверки | Что проверяет | Что сделал | После повторного скана |
|---|---|---|---|
| 15784 | Отключение автозапуска для всех типов носителей (`Turn off Autoplay` = `Enabled: All drives`) | В реестре `HKLM\SOFTWARE\Microsoft\Windows\CurrentVersion\Policies\Explorer` параметр `NoDriveTypeAutoRun` = `0xFF` | Passed |
| 15543 | Запрет анонимного перечисления учётных записей SAM | `RestrictAnonymousSAM` = `1` в `HKLM\SYSTEM\CurrentControlSet\Control\Lsa` | Passed |
| 15511 | Блокировка встроенной учётной записи «Гость» | `net user guest /active:no` | Passed |

## Результат

Оценка соответствия: **25% → 26%**. Закрыто 3 проверки из 424, поэтому прирост небольшой (около 0,7 пункта).

## Что осознанно не закрывал

Сложность и срок действия паролей, порог блокировки учётных записей: так удалённое администрирование стенда остаётся стабильным, а в учебной среде нет риска случайной блокировки.

## Выводы

- SCA показывает конкретные проверки и их статус, по ним можно вести план укрепления.
- Оценка в процентах мало говорит о защищённости: важнее приоритет проверок (анонимный доступ и автозапуск важнее косметических).
- Часть рекомендаций CIS конфликтует с удобством администрирования, их закрывают осознанно, а не «до 100%».
